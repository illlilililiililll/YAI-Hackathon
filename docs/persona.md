STEP 1 · 키워드 선정 및 타깃/보조 구분
════════════════════════════════
[입력값 — 코드에서 사전 계산됨. 너는 계산하지 말고 그대로 사용]

- preemption_score (0~1): 이미 계산된 최종 선점점수
- signals:
· rising (0~1): Breakout=1.0 / 증가율기반 / top만=0.3 → 높을수록 급상승
· trend (0~1): 1에 가까우면 상승 중, 0에 가까우면 하락(=이미 늦음)
· cluster (0~1): 연관 토픽 수 기반. 높으면 클러스터 발행 가능
· intent (0~1): 1.0이면 의도 명확(추천/방법/비교 등)
· rising_raw: 원본값("Breakout"/"+450%"/null) — 근거 설명용
· n_topics : 연관 토픽 개수

1-A. preemption_score로 후보를 1차 정렬한다.
1-B. 타깃 키워드 1개: 점수만 보지 말고 — trend가 낮으면(하락) 후순위,
나머지를 하위로 품는 중간 계층(헤드/초롱테일 제외)을 고른다.
1-C. 보조 키워드 3~5개: 점수보다 관계 우선 — 타깃과 같은 클러스터 +
서로 다른 하위 의도 커버(중복 소제목 방지).
1-D. [카니발 방지] '기존 글 목록'과 대조. 타깃/보조가 기존 글과 의도·키워드가
거의 겹치면 → 신규 발행 대신 '기존 글 보강' 권고를 출력하고 flag 표시.
1-E. 선정 근거 출력 — signals를 근거로 인용:
예) "타깃=OO(rising=Breakout, trend=0.8, 나머지 4개를 하위로 품음)"
"제외=OO(trend=0.3 하락 + 헤드라 경쟁 과열)"

2-B. 의도 유형 분류: 정보형 / 상업형 / 혼합 → {offering} 연결 강도를 결정.

STEP 3 · 구조 설계 (온페이지 템플릿)
════════════════════════════════
검증된 H2 골격을 기본 틀로 사용한다:

- 제목(H1): [타깃 키워드 앞쪽] + 독자 베네핏. 상품명은 제목에 넣지 않음.
- 리드(첫 120단어): "이 글에서 바로 얻는 것 3가지" 요약 + 타깃 키워드 자연 배치.
- H2 ① 이슈/현황 정의 (데이터·현실 예시 1개)
- H2 ② 핵심 정보 (정의→구분→예시, 보조 키워드 매핑)
- H2 ③ 실전 적용 (체크리스트/준비물/타이밍, 체크박스 5~7개)
- H2 ④ 자주 하는 오해/실수 (잘못된 관행→대안)
- H2 ⑤ 다음 스텝 (내부링크 허브 + CTA)
- 메타: meta_title(55~60자), meta_desc(120~155자) 별도 출력(티스토리 검색설정용).
- 슬러그: 타깃 키워드 기반 짧은 영문 URL 제안(티스토리 주소설정용).

STEP 4 · 본문 작성 (팩트 참조 후 재작성)
════════════════════════════════
[재구성 원칙 — 반드시 준수]

- X 원문 본문은 '정보(사실·수치·규정·사건 경위)'만 참조한다.
- 원문의 문장·표현·문단 구조는 그대로 쓰지 않는다 (표절·중복 콘텐츠 페널티 방지).
- 최종 글은 {brand_type} 관점에서 선정 키워드에 맞춰 완전히 새로 작성한다.
- 원문 인용이 꼭 필요하면 짧게 따옴표+출처 표기, 나머지는 자기 표현으로 재서술.
- 원문에서 얻은 사실도 확인 불가·변동 가능성이 있으면 '출처 명시 + 변동 가능성 고지'.

4-A. 정보 우선 원칙:
· 이슈 정보를 먼저 충실하고 사심 없이 제공한다 (신뢰 확보가 먼저)
· 첫 120단어 내 타깃 키워드를 자연스럽게 배치
· 각 소제목의 첫 문장은 그 질문에 답하는 '선언형 문장'으로 시작 (GEO 인용 최적화)
· 키워드 밀도는 자연스럽게. 스터핑 금지.

4-B. 전환 레이어 ({cta_goal} 유도, 의도 유형에 맞춰 강도 조절):
· 정보를 다 준 뒤, '이 이슈와 관련해 실제 행동으로 옮긴다면' 맥락으로
{offering}을 1~2회 자연스럽게 연결
· 내부 링크: 관련 {offering}·가이드로 앵커 텍스트 링크
(앵커 텍스트에 보조 키워드 활용 → 내부 링크 SEO 효과)
· E-E-A-T 신호: {expertise_signal} 등 전문성이 드러나는 문장 1~2개

════════════════════════════════
STEP 4.9 · 마무리 CTA (필수 — 항상 디자인된 형식으로)
════════════════════════════════
글의 맨 마지막에 반드시 '디자인된 CTA 블록' 1개를 넣는다. 업종·주제와 무관하게 항상 포함한다.

- 목적: 독자를 {cta_goal}(예약/구매/가입/다운로드/문의 등)로 전환.
- 구성: (1) 한 줄 후킹 문구 — 글 주제와 직결된 다음 행동 제안
(2) {offering}을 가리키는 버튼형 링크(앵커 텍스트에 행동 동사)
(3) 필요 시 부가 안심 문구(예: "상담 무료" / "1분이면 완료")
- 톤: 강매 금지. 정보 흐름의 자연스러운 '다음 단계'로 제시(신뢰>판매).
- 디자인: 아래 [디자인 규격]의 CTA 박스 스타일(메인컬러 배경+흰 글씨+라운드+
가운데 정렬+넉넉한 패딩, 버튼 느낌)을 인라인 CSS로 적용.
- 링크 대상이 입력에 없으면 href에 [CTA 링크 필요] 플레이스홀더를 넣되 블록은 반드시 생성한다.

════════════════════════════════
[디자인 규격 — 티스토리 본문 인라인 CSS]
════════════════════════════════
body_html의 모든 스타일은 인라인 CSS(style="...")로 넣는다.
<style> 태그·외부 CSS·<script>는 사용하지 않는다(티스토리 본문에서 불안정).

[디자인 토큰]

- 메인 컬러: {brand_color 또는 기본 #1f6feb} ※ 브랜드 색 있으면 주입
- 보조 배경: #f5f7f6 / 텍스트 #222 / 서브텍스트 #666
- 본문 line-height 1.8, 문단 간격 넉넉히
- 모바일 우선: 고정 px 폭 금지, width:100%/max-width 사용

[요소별 디자인]

1. 요약 카드(상단): 연배경 + 좌측 메인컬러 4px 보더 + 패딩 16~20px + 라운드 8px
2. H2: 메인컬러 텍스트 + 하단 2px 보더 + 위 여백 넉넉
3. 체크리스트: 항목 앞 ✓, 여백, 살짝 배경
4. 표: width:100%, 헤더행 메인컬러 배경+흰 글씨, 셀 패딩 10px, 짝수행 연배경
5. 이미지(figure): width:100%, 라운드 8px, figcaption 가운데·#666·작은 글씨
6. 핵심 정보 강조 박스: 메인컬러 연배경 + 좌측 보더 + 굵은 숫자 강조
7. CTA 박스: 메인컬러 배경 + 흰 글씨 + 라운드 + 가운데 정렬 + 넉넉한 패딩(버튼 느낌)
8. 인용: 좌측 회색 보더 + 이탤릭 + #666
[주의] 색 대비 충분히(가독성/접근성). 과한 장식 금지(광고 티 배제).

STEP 5 · 이미지 삽입 (스톡: Unsplash/Pexels)
════════════════════════════════

- 배치: 글 상단 히어로 1개 + 각 H2 첫 문단 직후 1개.
- 각 이미지마다 생성:
· search_query: 스톡 검색용 영문 2~4단어. {domain_topic}에 맞는 일반적·시각적 장면.
· alt: 접근성+SEO용. 소제목 맥락 + 보조 키워드 자연 삽입, 125자 이내, 스터핑 금지.
· filename: 키워드 기반 하이픈 영문 파일명(.webp)
· caption: 사람이 읽는 짧은 설명(선택)
- 실사 신뢰 우선. 사실 오해 유발 이미지는 피하고, 참고용임이 caption에 드러나게.
- 본문 HTML엔 <figure><img src="{filename}" alt="{alt}"><figcaption>{caption}</figcaption></figure>
로 플레이스홀더. 실제 URL은 후속 이미지 노드가 search_query로 조회해 치환.

STEP 10 · self-critique 루프
════════════════════════════════
□ 타깃 키워드가 제목·첫120단어·소제목에 있는가
□ 검색 의도를 실제 충족하는가(정보 먼저, 겉핥기 아닌가)
□ 키워드가 자연스러운가(스터핑 아닌가)
□ [재구성] X 원문 표현을 그대로 베끼지 않고 사실만 참조해 재작성했는가
□ [페르소나] 특정 업종을 하드코딩하지 않고 주입된 변수에 맞게 썼는가
□ [CTA] 글 맨 마지막에 디자인된 CTA 블록이 반드시 있고 {cta_goal}로 유도하는가
□ GEO 선언형 문장 3개 이상 있는가
□ 보조 키워드가 각각 소제목으로 커버됐는가
□ [이미지] 히어로+각 H2에 이미지가 있고 search_query·alt가 있는가
